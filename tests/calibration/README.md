# Calibration Manifests

Tool lists of real, well-known MCP servers, used to judge false positives by eye. They are not part of the pytest pass or fail checks. Run:

```
uv run python tests/calibration/run_calibration.py
```

It prints every finding per manifest and a count per rule. Rule changes are made only when two independent sources agree, so the rules are not tuned to one publisher. None of these servers contains hostile text, so this measures false positives only.

## What was copied, from where, and under which license

Only tool definitions were copied: tool names, titles, descriptions, parameter names, parameter descriptions, parameter types and limits, and annotations. Nothing else from these projects is included. Each source's license file is copied unchanged next to this README.

## How the manifests were made, and what was changed

- Nothing was executed. Source files and READMEs were downloaded as text and read. No server was run and no tool was called.
- Text is copied exactly. A check confirmed that every description string appears verbatim in its source: 88 for source 1, 218 for Playwright, and 613 for GitHub (multi-line parameter descriptions in the GitHub README are kept with their line breaks).
- Source 1 schemas are transcribed by hand from the zod (TypeScript) and pydantic (Python) definitions, because generating them would mean running the server code. They follow the definitions closely but leave out auto-generated pydantic titles and any additionalProperties setting from the schema libraries.
- Source 2 schemas come from the README lists, which give each parameter's name, type, required or optional, and description, but no enums, patterns, or limits. Where the README gives no type, none is written. Types such as string[] and string | null are written as an array of strings and as anyOf string or null.
- The Playwright README gives only a read-only flag, written as readOnlyHint. The GitHub README gives no annotations, so its tools have none: hint rule findings on GitHub (TG-SCH-004) are an artifact of the source, not of the real server.
- The GitHub README lists get_label under two toolsets; it is one tool and appears once.
- Two descriptions in the time server contain a value the server fills in at runtime (the local timezone). It is written as UTC.
- The only character change is escaping: the GitHub manifest has 6 non-ASCII characters, written as \u escapes so the ASCII-only test passes. No text was removed or reworded.
